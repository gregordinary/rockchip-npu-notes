# RK3588 — SoC parameter sheet

The hardware-validated reference target. This sheet is the per-SoC parameter summary;
the full hardware narrative is [../hardware-overview.md](../hardware-overview.md) and
the subsystem docs. Everything here is [HW sweep] or [source-confirmed] unless noted.

## NPU identity

- rknpu/NVDLA-derived, **3 cores**, marketed 6 TOPS (int8-conv peak).
- Driver: mainline `rocket` drm/accel, uAPI `CREATE_BO` / `SUBMIT` / `PREP_BO` /
  `FINI_BO`, one `/dev/accel/accelN`. Reached across cores by opening one fd per core.

## Machine parameters

These are the values `rocket_hw_profile` (`rocket_hw_rk3588`) carries.

| Parameter | Value | Notes |
|---|---|---|
| CBUF banks | 12 | `NPU_CBUF_BANKS` |
| CBUF bank size | 32768 B | 12×32 KB = 384 KB per core |
| Matmul tile cap (Mt/Nt) | 256 | the M-independent resident-weight pivot |
| Weight K-group, ≤2-byte dtypes | 32 | int8/int16/fp16/bf16 |
| Weight K-group, 4-byte dtypes | 16 | tf32 (4-byte halves it) |
| Weight N-group | 16 | |
| Datatype menu | int4/int8/int16/fp16/bf16/tf32 | complete; int16 output via int8 byte-decomposition |

## Register offset map

The offset map in [../../rocket-userspace/include/npu_hw.h](../../rocket-userspace/include/npu_hw.h)
is the RK3588's. Block bases: PC `0x0xxx`, CNA `0x1xxx`, CORE `0x3xxx`, DPU `0x4xxx`,
DPU-RDMA `0x5xxx`, PPU `0x6xxx`, PPU-RDMA `0x7xxx`. [source-confirmed: Mesa
`registers.xml`] The within-block offsets are IP-revision-specific — see the RK3576
sheet for a chip that re-packs the CNA block at the same block base.

## SoC integration

- **Core bases**: `npu@fdab0000`, `npu@fdac0000`, `npu@fdad0000`.
- **Clock**: compute clock `scmi_clk_npu` boots pinned at 200 MHz (vendor
  `POWER_DOWN_FREQ`); raising to 600 MHz is worth ~1.43× and must be done from inside
  the driver after the power domain is up. See [../perf/clock.md](../perf/clock.md).
- **IOMMU**: per-job attach/detach, each attach re-runs an MMU reset; keeping it
  attached same-fd saves ~20 µs/submit. See
  [../perf/iova-and-multicore.md](../perf/iova-and-multicore.md).
- **IOVA**: per-fd 4 GB window; N fds for N cores.

## Board-level machine parameters

From the Rockchip RK3588 Hardware Design Guide V1.4 [source-confirmed]. These are the
platform facts the NPU numbers in these notes were measured against; the RK3576 differs
on all three, so see [rk3576.md](rk3576.md) before carrying a number across.

| Parameter | Value |
|---|---|
| DRAM bus | **64-bit**, 4x 16-bit channels, LPDDR4/4X/5, max 32 GB |
| DRAM clock | 2112 MHz (`VDD_DDR_S0` at 0.870 V / 2.50 A / 2.18 W) |
| Theoretical peak bandwidth | ~33.8 GB/s |
| NPU rails | `VDD_NPU` **plus `VDD_NPU_MEM`** (405 mA, separately regulatable) |
| NPU peak | 0.850 V / 4.00 A / 3.40 W at 1000 MHz |
| NPU main capacitance | > 200 uF |
| Package / θJA | EHS-FCBGA, 8.7 C/W (JEDEC 2S2P reference figure, no heat sink) |

The separate `VDD_NPU_MEM` rail is the notable one: the RK3588 gives every major block
its own memory supply (`VDD_NPU_MEM`, `VDD_GPU_MEM`, `VDD_CPU_BIG0/1_MEM`,
`VDD_CPU_LIT_MEM`, `VDD_VDENC_MEM`) and combining it with the logic rail is documented as
a low-power-scenario concession. The RK3576 has no NPU memory rail at all.

The whole-chip ceiling is dispatch, not thermal, at this operating point — see
[../perf/](../perf/).
