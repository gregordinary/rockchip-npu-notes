# RK3566 — SoC parameter sheet

Planned; hardware incoming. This sheet is a placeholder to fill once the part is in
hand.

The RK3566/RK3568 carry the small rknpu: a **single core**, ~1 TOPS (int8), versus the
RK3588's 3 cores and the RK3576's 2. It is the target the upstream RK3568 `rocket` RFC
(per-SoC `num_cores` / `dma_bits` via DT) was written for, so it primarily stresses the
**core-count / DMA-width** axis of portability, where the RK3576 stresses the
**register-encoding** axis (its re-packed CNA/CORE/DPU geometry map).

Expected register layout: the RK3568 RFC reports the same NVDLA core as the RK3588 and a
matching register layout, so the RK3566 likely **shares the RK3588 geometry-register
encoding** and needs only a `rocket_hw_profile` (core count, DMA width, dtype menu), not
the per-chip regcmd encoder the RK3576 requires. Confirm on the part before relying on it.
The RK3568-class DMA path is 32-bit (IOVA < 4 GiB, GFP_DMA32) — a difference from both the
RK3588 and RK3576.

To fill in once bringing it up, mirroring the [rk3576.md](rk3576.md) layout:

- Machine parameters: CBUF banks + bank size, tile cap, weight tile-groups, datatype
  menu. Confirm on the part — do not assume RK3588 values.
- Register offset map: check whether the CNA block is re-packed (as on the RK3576) or
  matches the RK3588.
- SoC integration: core base(s), IRQ, power domain, clock, IOMMU, DMA address width.
