# RK3566 SoC parameter sheet

The RK3566 is planned, and the hardware is incoming. This sheet is a placeholder to fill
once the part is in hand.

The RK3566 and RK3568 carry the small rknpu: a single core at ~1 TOPS (int8), against the
RK3588's 3 cores and the RK3576's 2. The upstream RK3568 `rocket` RFC (per-SoC `num_cores`
/ `dma_bits` via DT) was written for this part. So it primarily stresses the core-count and
DMA-width axis of portability. The RK3576 stresses the register-encoding axis (its
re-packed CNA/CORE/DPU geometry map).

## Expected register layout

The RK3568 RFC reports the same NVDLA core as the RK3588 and a matching register layout.
So the RK3566 likely shares the RK3588 geometry-register encoding [expected]. It then needs
only a `rocket_hw_profile` (core count, DMA width, datatype menu), not the per-chip regcmd
encoder the RK3576 requires. Confirm on the part before relying on it. The RK3568-class DMA
path is 32-bit (IOVA < 4 GiB, GFP_DMA32), which differs from both the RK3588 and the RK3576.

## Sections to fill in

Fill these in at bring-up, mirroring the [rk3576.md](rk3576.md) layout:

- Machine parameters: CBUF banks + bank size, tile cap, weight tile-groups, datatype
  menu. Confirm on the part. Do not assume RK3588 values.
- Register offset map: check whether the CNA block is re-packed (as on the RK3576) or
  matches the RK3588.
- SoC integration: core base(s), IRQ, power domain, clock, IOMMU, DMA address width.
